# Decisions (defaults chosen under time pressure, and why)

| # | Decision | Why |
|---|---|---|
| 1 | Python 3.11 via `uv`; ffmpeg via `imageio-ffmpeg` (bundled static binary) | Machine had only Python 3.9 and no ffmpeg/brew. |
| 2 | Training runs through the official Fireworks cookbook `recipes/sft_loop.py` (`serverless=True`, LoRA r16/α32, lr 1e-4, 1 epoch, batch 16) in a separate venv `.venv-train` | It owns the GLM-5.3-Flash multimodal renderer (`glm53_flash`), datum construction, checkpointing and promotion; its torch/transformers pins conflict with the app venv. Verified offline that one image row renders to 1 `ImageChunk` (529 tokens) + text, 1,950 tokens total. |
| 3 | `rubric.csv` drafted by Claude from Merck/ASPCA/AAHA references, **not by a vet or a human** | No human author was available in the first hour. Flagged in README caveats; needs human review. |
| 4 | Never-list items are legal *output* vocabulary (in `plan.immediate`) but never in gold | Otherwise harmful advice would collapse into `parse_error` and `harmful_advice` could never be measured. |
| 5 | Split key for text = base scenario (dog/cat variants of a `both_*` row stay on one side); bootstrap cluster = `scenario_id` | Avoids leakage from sibling variants. |
| 6 | Image split by **near-duplicate group** (dihedral-invariant dHash, Hamming ≤10), ~13 test images/class × 3 messages | Cat dataset contains rotated/flipped copies of the same photo; file-level split would leak. |
| 7 | Image-row owner messages generated from one **generic** pattern for all classes (no lesion description) | Text must not leak the class; the model has to look at the image. |
| 8 | Train image rows: 1 message/image; test image rows: 3 messages/image | Keeps train ≈60/40 text/image without exploding training time. |
| 9 | Healthy classes map to `image_finding = no_visible_abnormality`, urgency `monitor_at_home` | Spec: model must learn to say monitor_at_home. |
| 10 | Train files are written right after generation; test files are *candidates* until human review → `apply_review_and_lock()` | Review only touches test rows, so training can launch before the 12:45 cutoff while teammates review. |
| 11 | Image dataset: HF `sanjayS059/Pet_disease` (dog, MIT) + `shahida12/Russiancat-skin-disease` (cat, **no license declared** → hackathon use only, not redistributed) | Only usable public sets found; no eye/ear/wound sets on HF. Kaggle unavailable (no creds). See `data/images/VERIFICATION.md`. |
| 12 | Label verification on 30-image contact sheets was done by a Claude subagent, not humans | Disclosed. 122 junk color-flooded dog images quarantined. |
| 13 | GLM calls send `reasoning_effort: low` (env `PT_REASONING_EFFORT`) | GLM-5.3 is thinking-only; `none` returns HTTP 400. Same setting for every system. |
| 14 | App: FastAPI + single-file `index.html` (vanilla JS), port 8031 | Spec's fallback; 8020 was taken on this machine. |
| 15 | App fail-safe: unparseable model output → `vet_today` + `needs_review` | Never return nothing to a worried owner; never under-triage on error. |
| 16 | Router merge never lowers urgency below the small model's answer | Escalation should only add caution. |
| 17 | `prices.json` = Fireworks Standard-tier list prices fetched 2026-11-02; LoRA priced as base (Fireworks: "same price as base models"); cached-input discount ignored | Conservative and reproducible. |
| 18 | Parser accepts two **structural** variants for every system: a flattened plan (`immediate`/`watch_for`/`prevent`/`recheck` at top level) and `image_finding: null`. Any out-of-vocabulary value is still a parse error (wrong on every field) | The rubric-in-prompt harness copied the rubric CSV's flat columns in 143/712 answers whose content was right; scoring that as wrong would measure formatting, not triage. Applied identically to all systems. |
| 19 | Owner messages generated by **Kimi K3 on Fireworks** (no OpenRouter key) | Spec default was an OpenRouter frontier model; the generator never sees labels, so the label pipeline is unchanged. |
| 20 | GLM-5.3-Flash LoRA must be served on a **dedicated 4×B300 deployment** (Fireworks: LoRAs can't be served serverless). Fine-tune $/1k = $60/h ÷ measured chats/h at concurrency 16, not per-token | That's the real serving cost of this deployment; it falls with higher utilisation. Base/harness are per-token serverless. |
| 21 | The LoRA run launched at 12:37 trained on text + image rows only. Video contact-sheet rows (`train_video.jsonl`) did not exist yet, so the fine-tune has **not** seen video-format inputs | Clips weren't collected before launch. Video eval still runs (frames + sheet through the same image path); README states this. |
| 22 | Serverless training returned `409 capacity_exhausted` for ~8 min; a retry wrapper (`scripts/train_retry.py`) relaunched every ~70 s and deleted orphan sessions. The first launch also crashed: macOS spawn re-imported the runner without a `__main__` guard (fixed) | Recorded so the run order is reproducible. |
| 23 | Test set locked at ~12:47 **without the two-teammate human review** (owner's call, time pressure). `review_test.csv` left blank: no rows dropped or relabelled | Disclosed in README caveats; labels are rubric-derived only. |
| 24 | `sft_safety` is computed offline from the saved `sft` outputs (same answers + rules), not a second model call | A second call adds run-to-run noise, so the comparison wouldn't isolate the rules. |
| 25 | Bug fix: safety rules now fire even when the model output fails to parse | Found during evaluation (xylitol messages with unparseable answers got no override). Regex gaps found the same way are documented, **not** patched, to avoid tuning on the test set. |
| 26 | Stopped at ~$60 of Fireworks spend (owner's $50 cap arrived after training + deployment): deployment force-deleted after 17 min, training session closed, PawTriage server stopped | Cost control. |
| 27 | PawTown game = care coordination, not engagement: points only for care actions, emergency freezes the game, helpers see no diagnoses, community signal hidden below 3 reports | Gamifying health must never reward delaying a vet visit. |
| 28 | Vets/dog parks from a one-time OpenStreetMap Overpass fetch (public mirrors were at capacity; a retry loop got through). If it had failed, the map would show no vets rather than invented ones | Real data or none. |
| 29 | App-only lenient parse (`salvage_output`): if strict parsing fails but urgency is valid, unknown vocabulary items are dropped and logged (`salvaged` audit), and the answer is flagged for review. **Scoring still uses strict `parse_output`** | In a live compare, one off-vocabulary word (e.g. `wash_hands_after_contact` under "prevent") turned a correct answer into a blanket fail-safe. Eval numbers are unchanged. |
| 30 | The fine-tune replay shows *recorded* test-set answers, clearly labeled, including a "show a miss" button | Shows what the LoRA said without a $60/h deployment, and doesn't hide failures. |
| 31 | Care adherence = due care steps done within 2 h of due ÷ due steps; "watch" quests are excluded | Measures what an owner can control. |
| 32 | Frontier row = `openai/gpt-6.1-terra-pro` via OpenRouter on all 712 rows (6-row pilot first; billed $2.97). TokenRouter was tried first, but the account had $0 credit and no calls went through | The owner supplied the key. A full-set run, not a subsample, so its CIs are comparable with the others. |
| 33 | Points are actually zeroed in the backend during an emergency (not just disabled in the UI), except for the emergency case's own steps and "at the vet" | The UI previously claimed a freeze the backend didn't enforce. |
